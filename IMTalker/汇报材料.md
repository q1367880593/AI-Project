# 租房经纪人 AI 陪练系统 — 项目汇报

## 一、项目概述

**爱聊对练（IMTalker）** 是一个基于大语言模型的租房经纪人对话训练系统。通过 AI 模拟真实客户，让经纪人在安全环境中进行对话练习，提升沟通技巧和业务转化能力。

**核心价值：** 用 AI 替代传统角色扮演培训，实现 7×24 小时可用的、标准化的、可量化的对话训练。

---

## 二、系统架构

### 整体架构

```
┌──────────────┐     ┌─────────────────┐     ┌──────────────┐
│  前端界面     │────▶│  Flask 后端      │────▶│  LLM 服务     │
│  (HTML/JS)   │◀────│  (chat_app.py)  │◀────│  (Ollama)     │
└──────────────┘     └────────┬────────┘     └──────────────┘
                              │
                     ┌────────▼────────┐
                     │  客户画像数据     │
                     │  customer_prompts│
                     └─────────────────┘
```

- **前端：** 单页 HTML 应用，三栏布局（画像选择 → 聊天区 → 会话参考）
- **后端：** Python Flask，负责加载画像数据、代理 LLM API 调用
- **LLM：** 支持 OpenAI 兼容接口（Ollama / DeepSeek / 通义千问等）
- **数据：** 客户画像以文件系统存储，按难度分目录

### Agent 编排设计（原型）

| 序号 | Agent | 职责 |
|------|-------|------|
| 1 | 场景导演 Agent | 读取场景/难度/画像，生成目标、隐藏顾虑、失败条件 |
| 2 | **客户模拟 Agent** ✅ 已实现 | 扮演客户，保持画像一致，根据经纪人回复调整态度 |
| 3 | 状态跟踪 Agent | 每轮更新信任度、意向度、需求完整度、烦躁度 |
| 4 | 实时复盘 Agent | 输出当前诊断、问题定位、红黄线、下一句建议 |
| 5 | 评分教练 Agent | 阶段结束后给出分数、优秀/待改进片段、训练建议 |

> 当前已实现第 2 项（客户模拟 Agent），其余 Agent 在原型设计阶段。

## 三、客户模拟机制

### 3.1 客户画像体系

每个虚拟客户由 **7 个维度** 定义：

| 维度 | 说明 | 示例值 |
|------|------|--------|
| 性格特征 | 回复风格和情绪倾向 | 果断型 / 谨慎型 / 分析型 / 挑剔型... |
| 租赁目的 | 租房动机 | 长期居住 / 不确定 / 短期过渡 |
| 决策模式 | 如何做决定 | 比较型 / 快速决策 / 价格驱动 / 被动型 |
| 价格敏感度 | 对价格的在意程度 | 高敏感度 / 中敏感度 / 低敏感度 |
| 意向阶段 | 当前处于哪个阶段 | 浏览阶段 / 咨询阶段 / 约看阶段 / 准备签约 |
| 沟通风格 | 信息开放程度 | 积极主动 / 信息开放 / 选择性开放 / 被动回应 |
| 核心需求 | 最看重的因素 | 地段 / 户型 / 预算 / 装修 / 养宠... |

### 3.2 行为参数（难度控制）

| 参数 | 入门 | 中等 | 高等 |
|------|------|------|------|
| 回复长度 | 短（1-3句） | 中（2-4句） | 长（5-10句） |
| 妥协意愿 | 70% | 50% | 20% |
| 异议概率 | 15% | 30% | 55% |
| 留资意愿基线 | 35% | 20% | 5% |
| 留资满意度阈值 | 55 | 65 | 85 |
| 最大不匹配次数 | 6 | 4 | 2 |
| 隐藏需求概率 | 5% | 15% | 25% |

### 3.3 结构化输出

AI 客户每条回复都以 JSON 格式输出，包含三个字段：

```json
{
    "response": "客户回复的具体内容",
    "action": "chat / leave_phone / refues",
    "action_reason": "内部决策依据"
}
```

- **chat** — 继续对话，默认行为
- **leave_phone** — 愿意留联系方式（高门槛，需满足特定触发条件）
- **refuse** — 结束对话（低门槛，经纪人犯错即触发）

### 3.4 决策引擎

AI 客户根据 prompt 中定义的决策逻辑自主判断：
- 综合满意度评分（0-100）
- 拒绝触发条件（连续不匹配、态度敷衍、无法回答专业问题）
- 留资触发条件（推荐匹配、展示专业能力、解决异议）
- 变异机制（触发点机制导致行为突变）

## 四、功能特性

### 已实现

| 功能 | 说明 |
|------|------|
| 客户画像选择 | 20 个客户画像，4 个难度级别（入门/中等/中高/高等） |
| AI 客户对话 | 实时与 AI 客户进行文字对话，模拟 IM 聊天场景 |
| 结构化反馈 | 每条客户回复标注 action 标签和决策理由 |
| 真实会话参考 | 5 条匹配的真实客服对话记录，供经纪人参考话术 |
| Prompt 查看 | 随时查看当前客户的完整模拟提示词 |
| 快捷话术 | 一键插入常用开场白、询问预算、推荐房源等话术 |
| 留资/拒绝提示 | 客户留资或拒绝时醒目提示对话目标达成/失败 |
| 多 LLM 支持 | 兼容 OpenAI / Ollama / DeepSeek 等接口 |

## 六、使用流程

```
1. 启动 LLM 服务（ollama serve）
2. 启动 Flask 服务（python chat_app.py）
3. 浏览器打开 http://localhost:7788
4. 配置 API 地址和模型
5. 选择难度 → 选择客户画像
6. 在输入框发送消息，开始与 AI 客户对话
7. 右侧查看真实会话参考，顶部可查看 Prompt
```

## 七、数据说明

- 客户画像来源于 `customer_prompts/` 目录下的 `system_prompt.txt`
- 每份画像包含 5 条真实客服对话记录（`conversation_*.txt`），经过标签分类匹配
- 对话记录来自真实 IM 聊天数据，包含客户 ID、经纪人 ID、业务类型、标签匹配详情
- 当前共 20 个客户画像，覆盖 4 个难度级别
